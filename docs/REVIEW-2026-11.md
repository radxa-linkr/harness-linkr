# Review and hardening pass (November 2026)

A structured review of every integration in this repository: the shared transport
(`core/`, materialized into `dsh-linkr/lib/`), the MCP server (`mcp-linkr/`), the
DSH plugin (`dsh-linkr/`), and the OpenCode 2 native plugin plus its web and
desktop panels (`opencode/plugin/`). Each finding below was fixed, covered by a
test where the behaviour is testable, and verified with `node scripts/test-all.mjs`.

## Transport (`core/`)

| Finding | Fix |
|---|---|
| A killed process could leave the device in a session video mode with nobody to restore it (the DSH plugin never journalled) | Journal + recovery moved into `core/journal.js` / `core/recover.js`, shared by the MCP server and the DSH plugin; the client reports `onSessionEnd({reason, restored})` |
| The MCP server released its cross-process device lease even when the mode restore had failed, handing a stuck device to another app | Release only when `restored === true`; otherwise the lease and the retry path stay |
| `dispose()` was not idempotent and re-reported session end on a second call or on disconnect-after-dispose | Shared `#disposePromise`, and a session end is reported only when a session or mode debt existed |
| A late `close`/`message` from a replaced media socket tore down the newly started session (and its ffmpeg child) | Handlers capture their socket and ignore events when it is no longer `#ws` |
| H.264 packets were written into ffmpeg without backpressure (unbounded Node buffer when the decoder stalled) | Drop packets until `drain` and count them in `stats.dropped` |
| Two concurrent clipboard calls could both pass the `#pending` check while awaiting the socket/token | `#requesting` is set synchronously at entry; a second caller gets the existing "busy" sentence |

## MCP server (`mcp-linkr/`)

- Saved-settings validator accepted only 1–30 fps while the transport, DSH plugin
  and README allow 60; aligned (and the MCP panel input/notes too).
- MJPEG fan-out now honours socket backpressure (newest frame only).
- `linkr_panel`/settings/panel bridges unchanged externally; the panel failure
  sentence reaches `/state.json` so the UI can show the real reason (e.g. the
  device lease being held by another local app).

## DSH plugin (`dsh-linkr/`)

- `baseUrl` is parsed as a URL and must be a bare origin; saved value is
  canonicalised to `url.origin` (no credentials/path/query).
- Settings writes are ordered: durable row first, password second, with the row
  rolled back if the credential store fails; a failed row write never touches the
  password store.
- Live MJPEG stream honours socket backpressure.
- The Host now writes/clears the shared video-mode journal through the client
  hooks and repairs a leftover journal before building its first client.
- Closing the last panel stream ends a panel-started session after an 8 s grace
  (agent-used sessions are left to `idleStopMs`).

## OpenCode 2 plugin and panels (`opencode/plugin/`)

- Code review fixes: no replay of a previous session's last frame, settings button
  always reachable, appearance effect no longer reloads the iframe twice, state
  errors clear stale metrics, stricter settings validation, mainframe ABI left to
  the host.
- The desktop sidebar panel follows the app theme, carries an in-place connection
  settings form (persisted to `~/.linkr/opencode-plugin.json`, 0600), reconnects
  when a reload left the iframe on a dead panel port, keeps the session alive
  while mounted, and releases a panel-started session after the last viewer.
- The desktop app loads `./gui-experimental` only from plugins configured
  globally; documented in the plugin README and `docs/E2E-OPENCODE.md`.

## Known limitations (not defects, left for later)

- The desktop-panel visual check is manual: the Electron webview is not exposed to
  headless inspection.
- A full-suite run once reported the private-login suite as failed under load; the
  suite passes in isolation and in repeated full runs. The test harness gives the
  MCP children a 20 s request budget; contention with other suites is the likely
  cause and no product code is involved.
- DSH `state.videoMode` shows the last observed mode while disconnected (it is not
  re-read from the device on every poll); normal restores update it to the baseline.
